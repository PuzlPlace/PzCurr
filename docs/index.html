Dinheiro com precisão exata em PHP

PzCurr é uma biblioteca para representar, calcular e persistir valores monetários sem os erros clássicos de float. Pensada para Laravel, mas utilizável em qualquer projeto PHP com BCMath.

BCMath ISO 4217 Laravel Cast NF-e Zero float no domínio

O que é o PzCurr?

O PzCurr implementa o padrão Money (Martin Fowler): um tipo dedicado para valores monetários, com moeda, escala (casas decimais) e operações seguras. Em vez de guardar 19.90 como float ou decimal solto, você trabalha com um objeto que sabe quanto vale e em qual moeda.

Precisão exata

Toda aritmética usa BCMath sobre strings. Não há conversão para float nos cálculos.

API fluente

Encadeie operações: of('10')->add('5')->multiply('2'). Legível e expressivo.

Laravel pronto

Cast Eloquent em duas colunas (amount + currency), Service Provider e config publicável.

Brasil em mente

Moeda padrão BRL, formatação pt-BR, cenários de NF-e com escala alta e arredondamento HALF_UP.

O ponto de entrada é sempre a Factory:

use Puzl\PzCurr\Factory\PzCurrFactory;

PzCurrFactory::make()
    ->of('25.00')      // moeda omitida → BRL
    ->add('4.99')
    ->format();          // 'R$ 29,99'

Você depende apenas da interface PzCurrInterface — nunca do adapter concreto (PzCurrBcMath).

Por que não usar float ou decimal solto?

Em PHP (e na maioria das linguagens), float segue o padrão IEEE 754. Muitos decimais — como 0.1 — não têm representação exata em binário. Isso gera surpresas em somas, comparações e persistência.

// Problema clássico em PHP puro:
var_dump(0.1 + 0.2 === 0.3);  // bool(false)

// Com PzCurr (strings + BCMath):
PzCurrFactory::make()->of('0.1')->add('0.2')->isEqualTo('0.3');  // true

Em sistemas financeiros, e-commerce, folha de pagamento ou emissão de notas fiscais, centavos “perdidos” viram divergência contábil, rejeição na SEFAZ ou reclamação de cliente. O PzCurr existe para evitar isso desde o primeiro of() até o save() no banco.

Inspiração
A ideia é a mesma de bibliotecas consagradas como Money PHP e Dinero.js: tratar dinheiro como valor de primeira classe, não como número genérico.

O que faz e o que não faz

✓ O PzCurr faz

  • Criar valores a partir de string, int ou centavos (ofMinor)
  • Somar, subtrair, multiplicar, dividir, módulo
  • Comparar valores (mesma moeda)
  • Arredondar com vários modos (HALF_UP, HALF_EVEN, …)
  • Alterar escala (withScale) — útil em NF-e
  • Dividir valor entre partes (split, allocate) sem perder centavos
  • Formatar para exibição (pt-BR ou locale com intl)
  • Serializar para JSON/array sem float
  • Persistir no Eloquent via PzCurrCast
  • Registrar moedas customizadas (cripto, tokens internos)

✗ O PzCurr não faz

  • Conversão cambial — não há taxa de câmbio nem USD→BRL automático
  • Operar moedas diferentes na mesma expressão (lança exceção)
  • Substituir regras fiscais — ICMS, PIS, tolerâncias SEFAZ são sua responsabilidade
  • Garantir imutabilidade — o objeto é mutável; use copy() quando precisar
  • Validar XML de NF-e — só ajuda no cálculo decimal
  • Adapters Brick/MoneyPHP (previstos, ainda caem no BCMath)

Início rápido

Três linhas para o caso mais comum — real brasileiro, sem informar moeda:

use Puzl\PzCurr\Factory\PzCurrFactory;

$total = PzCurrFactory::make()
    ->of('25.00')       // = of('25.00', 'BRL')
    ->add('4.99')
    ->format();

echo $total;  // R$ 29,99

Para ler o valor “cru” (string, nunca float):

$money = PzCurrFactory::make()->of('19.90', 'BRL');

$money->getAmount();      // '19.90'
$money->getMinorAmount(); // 1990 (centavos)
$money->toArray();        // ['amount'=>'19.90','currency'=>'BRL','scale'=>2]

Conceitos-chave

1. Amount é sempre string

O valor interno é uma string decimal ('19.90'). Isso é intencional: BCMath opera sobre strings e evita perda de precisão. Use getAmount() ou toDecimal() para persistir ou enviar em APIs.

2. Moeda (currency)

Cada instância carrega um código ISO 4217 (ex.: BRL, USD, JPY). Operações entre instâncias exigem a mesma moeda; caso contrário, PzCurrencyMismatchException.

3. Escala (scale)

Número de casas decimais da instância. BRL usa 2 por padrão; JPY usa 0. Você pode forçar escala maior em of() para cálculos intermediários (ex.: unitário de NF-e com 10 casas).

4. Unidade menor (minor)

Centavos para BRL: ofMinor(1990, 'BRL') ≡ of('19.90', 'BRL'). Útil para gateways de pagamento e APIs que trabalham em inteiros.

5. Factory → Interface

PzCurrFactory::make() devolve PzCurrInterface. O adapter concreto (hoje só BCMath implementado) fica encapsulado.

Moedas e escala

Enum recomendado

use Puzl\PzCurr\Enum\PzCurrCurrencyEnum;
use Puzl\PzCurr\Factory\PzCurrFactory;

PzCurrFactory::make()->of('10.00', PzCurrCurrencyEnum::USD);
PzCurrFactory::make()->of('100', PzCurrCurrencyEnum::JPY);  // escala 0

String continua válida: of('10.00', 'BRL') — necessário para moedas customizadas e reidratação do Cast.

Escala explícita

// Escala da moeda (BRL = 2)
PzCurrFactory::make()->of('1.50');

// Escala customizada — prevalece em todas as operações
PzCurrFactory::make()
    ->of('1.1234567', PzCurrCurrencyEnum::BRL, scale: 7)
    ->add('0.0000001')
    ->multiply('2');
// getAmount() => '2.0000002'

Moeda customizada

use Puzl\PzCurr\Currency\PzCurrCurrency;
use Puzl\PzCurr\Currency\PzCurrCurrencyRegistry;

PzCurrCurrencyRegistry::register(new PzCurrCurrency(
    code: 'BTC',
    numericCode: 0,
    scale: 8,
    symbol: '₿',
));

PzCurrFactory::make()->of('0.00000001', 'BTC');

O enum PzCurrCurrencyEnum lista dezenas de moedas ISO; metadados (escala, símbolo) vêm do PzCurrCurrencyRegistry.

Mutabilidade e copy()

Os métodos de operação (add, subtract, etc.) alteram o objeto atual e retornam $this para encadeamento. Isso é diferente de bibliotecas imutáveis como Money PHP clássico.

$base = PzCurrFactory::make()->of('100.00', 'BRL');

$comImposto = $base->copy()->multiply('1.1');   // 110.00
$semImposto = $base->copy();                  // 100.00
// $base continua 100.00
Atenção
Se você passar a mesma instância para vários lugares e chamar add() em um deles, todos “enxergam” o valor alterado. Use copy() antes de ramificar cálculos.

Float e modo STRICT

Por padrão, float é aceito em of, add, multiply, etc., mas convertido para string de forma determinística (number_format na escala da instância). O ideal é sempre usar string: '19.90'.

Nunca use toFloat() em cálculos
toFloat() existe só para interoperabilidade ou exibição legada. Para persistir, comparar ou somar, use getAmount() (string) ou getMinorAmount() (int).

Com PZCURR_STRICT_FLOATS=true (ou strict_floats => true na config), qualquer float lança PzCurrFloatNotAllowedException.

Criação de valores

of(string|int|float $amount, ?currency = null, ?int $scale = null): self

Cria a partir do valor decimal. Moeda omitida → BRL. Arredonda para a escala na criação.

ofMinor(int $minorAmount, ?currency = null): self

Cria a partir de centavos (ou unidade menor da moeda). Ex.: ofMinor(1990, 'BRL') → 19,90.

zero(?currency = null, ?int $scale = null): self

Inicializa com zero na moeda informada.

Vários operandos de uma vez

PzCurrFactory::make()
    ->of('100.00', 'BRL')
    ->subtract('10.00', '5.50', '2.00');
// getAmount() => '82.50'

// Spread de array
$itens = ['4.99', '10.00', '3.50'];
PzCurrFactory::make()->of('0.00')->add(...$itens);

Exemplo: total de pedido

$total = PzCurrFactory::make()
    ->of('25.00', 'BRL')
    ->add('4.99')
    ->subtract('2.50')
    ->multiply('2');
// '54.98'

Arredondamento e escala

Altera casas decimais com arredondamento. Ex.: reduzir cálculo de 10 casas para 2 no vProd da NF-e.

Define o modo padrão para operações seguintes.

Modos disponíveis

PzCurrFactory::make()
    ->of('10.00', 'BRL')
    ->divide('3', PzCurrRoundingModeEnum::HALF_UP);
// '3.33'

allocate() e split()

Problema clássico: dividir R$ 100,00 entre 3 pessoas. 100/3 dá 33,33… e a soma das partes não fecha em 100,00.

O PzCurr usa o algoritmo do maior resto: a soma das partes é sempre igual ao valor original; centavos extras vão para quem tem maior resto fracionário.

$dinheiro = PzCurrFactory::make()->of('100.01', 'BRL');
$partes = $dinheiro->split(3);
// Ex.: '33.34', '33.33', '33.34' — soma = 100.01

// Proporções customizadas (ex.: 70% / 30%)
$partes = PzCurrFactory::make()
    ->of('0.05', 'BRL')
    ->allocate([7, 3]);

Cada parte retornada é uma cópia independente (copy() interno). Mutar uma parte não afeta as outras.

Integração Laravel

Eloquent Cast

O PzCurrCast persiste em duas colunas — nunca em um único decimal float:

// Migration
$table->decimal('price_amount', 20, 8);
$table->char('price_currency', 3);

// Model
protected $casts = [
    'price' => PzCurrCast::class,
];

// Uso
$order->price = PzCurrFactory::make()->of('19.90', 'BRL');
$order->save();
// price_amount = '19.90', price_currency = 'BRL'

$order = Order::find(1);
echo $order->price->format();  // R$ 19,90
Zero float no caminho de persistência
O Cast grava e lê strings. Nenhuma conversão para float ocorre no get/set.

NF-e e NFC-e

Em notas fiscais eletrônicas, campos como vUnCom aceitam até 10 casas decimais, qCom até 4, mas vProd deve ter exatamente 2. A SEFAZ valida com tolerância de R$ 0,01 e arredondamento HALF_UP.

$vProd = PzCurrFactory::make()
    ->of('1.0640000000', PzCurrCurrencyEnum::BRL, scale: 10)
    ->multiply('39680.1234')
    ->withScale(2);

echo $vProd->getAmount();  // '42219.65'

Consulte também o documento interno NFE-NFCE-CASAS-DECIMAIS-ARREDONDAMENTO.md no repositório para regras detalhadas de validação SEFAZ.

Boas práticas

  1. Use strings para valores monetários: '19.90', não 19.90.
  2. Ative STRICT em produção se quiser garantir que ninguém passe float acidentalmente.
  3. Use copy() antes de ramificar cálculos a partir do mesmo objeto.
  4. Persista amount + currency — nunca um único campo float/decimal sem moeda.
  5. getAmount() para banco e API; format() só para UI.
  6. withScale(2) no final de pipelines NF-e, após multiplicações com escala alta.
  7. allocate/split para rateios — não faça valor / n manual em float.
  8. Dependa de PzCurrInterface, não de PzCurrBcMath diretamente.

Perguntas frequentes

PzCurr substitui Money PHP ou Brick Money?

Não diretamente. É uma biblioteca própria da Puzl, focada em BCMath + Laravel. Adapters MoneyPHP/Brick estão previstos mas hoje fazem fallback silencioso para BCMath.

Posso usar sem Laravel?

Sim. Instancie via PzCurrFactory::make() ou new PzCurrBcMath(). Config e Cast são opcionais.

Por que o objeto é mutável?

API fluente e menor alocação em encadeamentos longos. Imutabilidade é opt-in via copy().
